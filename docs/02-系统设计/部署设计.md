## 1. 部署架构

系统采用「Nginx + 前端静态资源 + Spring Boot 后端 + MySQL + Redis（可选）」的部署架构。三端前端构建为静态资源由 Nginx 托管，后端以可执行 JAR 独立运行，Nginx 反向代理 `/api` 到后端，同域部署规避跨域问题。

```
                    ┌──────────────┐
   用户/商家/管理员 → │   浏览器（三端） │
                    └──────┬───────┘
                           │ HTTPS/HTTP
                    ┌──────▼───────┐
                    │    Nginx     │  静态资源 + 反向代理 + 负载均衡
                    └───┬──────┬───┘
            静态资源    │      │  /api 反向代理
              ┌─────────┘      └────────┐
       ┌──────▼──────┐          ┌───────▼──────┐
       │ 前端静态目录 │          │ Spring Boot  │  后端服务（可多实例）
       │  dist/      │          │  :8080       │
       └─────────────┘          └───┬──────┬───┘
                                    │      │
                          ┌─────────┘      └────────┐
                   ┌──────▼──────┐         ┌───────▼──────┐
                   │  MySQL 8    │         │  Redis（可选）│
                   │  业务主库    │         │  缓存/会话    │
                   └─────────────┘         └──────────────┘
```

对应的 PlantUML 源文件：`docs/uml/部署图.puml`。

## 3. 本地部署步骤

### 3.1 数据库初始化

1. 启动 MySQL 8，创建数据库：
```sql
CREATE DATABASE IF NOT EXISTS fruit_trade_db
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```
2. 导入后端提供的建表脚本 `sql/init.sql`（由后端智能体落盘，见《数据库设计》）。
3. 确认账号具备建表与增删改查权限。

### 3.2 后端启动

1. 配置 `backend/src/main/resources/application.yml`（详见第 5 节配置项清单），填写数据库连接、JWT 密钥。
2. 编译并启动：
```bash
cd backend
mvn clean package -DskipTests
java -jar target/fruit-trade-backend.jar
```
3. 验证：访问 `http://localhost:8080/api/products` 返回统一响应即成功。

### 3.3 前端启动（开发模式）

```bash
cd frontend
npm install
npm run dev
```
浏览器访问 Vite 提示地址（默认 `http://localhost:5173`），Axios  baseURL 指向 `http://localhost:8080/api`。

### 3.4 默认测试账号

| 角色 | 用户名 | 密码 | 说明 |
|------|--------|------|------|
| ADMIN | admin | 123456 | 平台管理员（初始化 SQL 插入） |
| MERCHANT | merchant01 | 123456 | 商家（注册后需审核通过） |
| USER | user01 | 123456 | 普通用户 |

> 测试账号以实际初始化 SQL 为准。

## 4. 生产部署建议

1. **后端**：`java -jar` 配合 `systemd` 托管，设置开机自启与崩溃重启；多实例时由 Nginx 负载均衡。
2. **前端**：执行 `npm run build` 生成 `dist/`，部署到 Nginx 静态目录；开启 gzip 与长缓存（带 hash 的静态资源）。
3. **Nginx**：配置 `/api` 反向代理到后端，`proxy_set_header` 传递真实 IP；启用 HTTPS（TLS 证书）。
4. **数据库**：独立部署，关闭公网访问，仅允许后端网段；开启慢查询日志。
5. **缓存**：Redis 独立部署，配置密码与最大内存；不可用时应用降级到本地缓存。
6. **安全**：修改默认密码与 JWT 密钥，最小化开放端口，定期更新依赖补丁。
7. **日志**：后端日志落盘并轮转，Nginx 访问日志集中收集。

Nginx 关键配置示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/fruit-trade/dist;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

## 6. 备份与监控

### 6.1 数据备份

- 每日定时全量备份：`mysqldump -u root -p fruit_trade_db > backup_$(date +%F).sql`。
- 保留最近 30 天备份，定期异地存储；升级或数据变更前后额外备份。
- 教学环境可用 MySQL Workbench 或 `mysqldump` 手动备份。

### 6.2 监控

- 应用健康：Spring Boot Actuator `/actuator/health`（生产限制访问）。
- JVM 监控：堆内存、线程数、GC 情况（Actuator + Prometheus 可选）。
- 数据库监控：连接数、慢查询、磁盘空间。
- 业务监控：下单失败率、支付成功率、预警数量趋势（可由报表接口观察）。
- 日志告警：ERROR 日志、接口 5xx 错误达到阈值时通知管理员。

## 7. 故障排查

| 现象 | 可能原因 | 排查与处理 |
|------|----------|------------|
| 后端启动失败 | 端口占用 / 数据库连不上 | 检查 `server.port`；核对数据源 URL、账号密码、MySQL 是否运行 |
| 接口返回 401 | Token 缺失或过期 | 检查请求头 `Authorization`；重新登录获取 Token |
| 接口返回 403 | 角色权限不足 / 商家未审核 | 确认账号角色与 `audit_status`；管理员先审核商家 |
| 前端页面空白 | 静态资源路径错误 / 构建失败 | 检查 Nginx `root` 与 `try_files`；重新 `npm run build` |
| 商品列表为空 | 无上架商品 / 逻辑删除条件 | 确认 `status=1`、`deleted=0`；商家先上架商品 |
| 下单提示库存不足 | 库存预占并发 / 库存为 0 | 检查 `inventory.stock`；补货后重试；关注乐观锁冲突 40902 |
| 中文乱码 | 字符集不一致 | 确认数据库/表 utf8mb4、连接参数 `characterEncoding=utf8` |
| 预警不更新 | 定时任务未执行 | 检查 `warning.scan.cron` 与任务日志；手动触发验证 |
| 跨域错误 | 开发环境未配 CORS | 检查 `CorsConfig` 允许的 Origin；生产走 Nginx 同域 |
