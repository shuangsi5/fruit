## 1. 数据库总体约定

### 1.1 基本信息

| 项目 | 约定 |
|------|------|
| 数据库名 | `fruit_trade_db` |
| 字符集 | `utf8mb4`（完整支持中文与 emoji） |
| 排序规则 | `utf8mb4_unicode_ci` |
| 存储引擎 | InnoDB（事务、行锁、外键） |
| 主键策略 | `BIGINT UNSIGNED AUTO_INCREMENT`，Java 端对应 `Long` |
| 时间类型 | `DATETIME`，创建时间默认 `CURRENT_TIMESTAMP`，更新时间 `ON UPDATE CURRENT_TIMESTAMP` |
| 金额类型 | `DECIMAL(10,2)`，禁用 `FLOAT/DOUBLE` 避免精度丢失 |
| 命名规范 | 蛇形命名 `snake_case`；表名复数语义清晰；索引 `idx_` 前缀，唯一索引 `uk_` 前缀 |

### 1.2 审计字段约定

除日志类表（`inventory_log`、`recommendation_log`）仅保留 `create_time` 外，其余业务表统一包含以下审计字段：

| 字段名 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `create_time` | DATETIME | CURRENT_TIMESTAMP | 创建时间 |
| `update_time` | DATETIME | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 更新时间 |
| `deleted` | TINYINT | 0 | 逻辑删除标记：0 未删除，1 已删除 |

> 所有查询必须附加 `deleted = 0` 条件（MyBatis-Plus 逻辑删除插件自动处理）。

### 1.3 外键约束策略

- **逻辑外键为主**：表间通过 `xxx_id` 字段关联，建立普通索引，不在数据库层强制 `FOREIGN KEY` 约束，由应用层保证引用完整性。理由：便于逻辑删除、数据迁移与教学演示。
- **关键强一致场景**（订单-明细、支付-订单）在应用事务内校验，必要时可加物理外键。
- 删除策略：业务数据一律逻辑删除；订单、支付、售后、审核记录不允许物理删除。

## 2. 完整表清单

系统共设计 **17 张表**，覆盖账号、商家、商品、库存、交易、售后、投诉、审核、推荐与日志全链路。

| 序号 | 表名 | 中文名 | 说明 |
|------|------|--------|------|
| 1 | `sys_user` | 系统用户表 | 三端账号统一存储，role 区分角色 |
| 2 | `merchant` | 商家表 | 商家资质信息与审核状态 |
| 3 | `category` | 商品分类表 | 支持二级分类（parent_id） |
| 4 | `product` | 商品表 | 商品主信息、价格、保质期、销量 |
| 5 | `product_image` | 商品图片表 | 一商品多图 |
| 6 | `inventory` | 库存表 | 与商品 1:1，可用/锁定库存、安全库存、预警等级 |
| 7 | `cart` | 购物车表 | 用户-商品选购关系 |
| 8 | `address` | 收货地址表 | 用户收货地址 |
| 9 | `orders` | 订单主表 | 订单头信息、金额、状态、收件冗余 |
| 10 | `order_item` | 订单明细表 | 订单内商品快照 |
| 11 | `payment_record` | 支付记录表 | 模拟支付流水 |
| 12 | `logistics` | 物流表 | 运单号、轨迹、签收信息 |
| 13 | `after_sale` | 售后表 | 退款/退货/换货申请与处理 |
| 14 | `complaint` | 投诉表 | 用户投诉及处理 |
| 15 | `audit_record` | 审核记录表 | 审核操作留痕（商家/售后/投诉） |
| 16 | `inventory_log` | 库存流水表 | 库存每一次变动记录 |
| 17 | `recommendation_log` | 推荐记录表 | 推荐结果及算法来源留痕 |

### 2.1 表关系概览

```
sys_user 1──1 merchant          （商家账号，user_id）
sys_user 1──N address
sys_user 1──N cart ──N product
category 1──N product
merchant 1──N product
product  1──1 inventory
product  1──N product_image
product  1──N inventory_log
orders   N──1 sys_user
orders   N──1 merchant
orders   N──1 address
orders   1──N order_item ──N product
orders   1──1 payment_record
orders   1──1 logistics
orders   1──N after_sale ──1 order_item（可选）
after_sale / complaint ──N audit_record
sys_user 1──N complaint ──N merchant
sys_user 1──N recommendation_log ──N product
```

## 4. 关键字段枚举定义

### 4.1 角色 role（sys_user）
`USER` 普通用户 / `MERCHANT` 商家 / `ADMIN` 平台管理员

### 4.2 订单状态 status（orders）

| 值 | 名称 | 英文标识 | 说明 |
|----|------|----------|------|
| 0 | 待支付 | PENDING_PAYMENT | 订单创建，等待支付 |
| 1 | 待发货 | PENDING_SHIPMENT | 支付成功，等待商家发货 |
| 2 | 运输中 | SHIPPING | 已发货，物流配送中 |
| 3 | 已完成 | COMPLETED | 用户确认收货或超时自动完成 |
| 4 | 已取消 | CANCELLED | 用户取消或支付超时关闭 |
| 5 | 售后中 | AFTER_SALE | 进入售后流程 |

### 4.3 售后状态 status（after_sale）
`0` 待审核 / `1` 审核通过 / `2` 处理中 / `3` 已完成 / `4` 已驳回

### 4.4 商家审核状态 audit_status（merchant）
`0` 待审核 / `1` 审核通过 / `2` 审核驳回

### 4.5 商品状态 status（product）
`0` 下架 / `1` 上架

### 4.6 预警等级 warning_level（inventory）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | 正常 NORMAL | 库存与保质期均健康 |
| 1 | 注意 NOTICE | 轻度风险，需关注 |
| 2 | 警告 WARNING | 中度风险，需处理 |
| 3 | 严重 CRITICAL | 高风险，需立即处理 |

### 4.7 支付方式 pay_method
`1` 模拟微信支付 / `2` 模拟支付宝 / `3` 余额支付（预留）

### 4.8 支付状态 status（payment_record）
`0` 待支付 / `1` 成功 / `2` 失败 / `3` 已退款

### 4.9 库存变动类型 change_type（inventory_log）
`1` 采购入库 / `2` 销售出库 / `3` 售后回补 / `4` 盘点调整 / `5` 锁定 / `6` 释放

### 4.10 投诉状态 status（complaint）
`0` 待处理 / `1` 处理中 / `2` 已处理 / `3` 已关闭

## 6. 索引设计与查询优化考虑

| 表 | 高频查询场景 | 索引设计 |
|----|--------------|----------|
| sys_user | 登录按账号、按角色筛选 | `uk_username`、`idx_role`、`idx_merchant` |
| product | 上架商品列表（按分类/商家/销量） | `idx_status` + `idx_category` + `idx_sales`，名称前缀索引 |
| inventory | 商家库存预警查询 | `uk_product`、`idx_merchant`、`idx_warning` |
| orders | 用户订单列表、商家订单、按状态筛选 | `idx_user`、`idx_merchant`、`idx_status`、`idx_create_time` |
| order_item | 按订单查明细 | `idx_order` |
| cart | 按用户查购物车、去重校验 | `uk(user_id, product_id)` |
| after_sale | 商家/用户售后列表 | `idx_merchant`、`idx_user`、`idx_status` |
| inventory_log | 按商品查流水、按时间趋势 | `idx_product`、`idx_create_time` |
| recommendation_log | 按用户查推荐历史 | `idx_user`、`uk(user_id, product_id)` |

优化原则：

1. **最左前缀**：组合索引按查询频率与区分度排列，避免冗余单列索引。
2. **覆盖索引**：列表接口仅查询必要字段，减少回表。
3. **分页优化**：深分页采用游标（基于 id 或时间）替代大 `OFFSET`。
4. **避免索引失效**：不在索引列上使用函数、避免隐式类型转换、`LIKE` 前缀通配会导致失效。
5. **逻辑删除条件**：所有查询带 `deleted = 0`，可与业务索引组成联合索引。
6. **统计报表**：销售总览按日预聚合或走主从分离，避免大表实时聚合影响交易。
7. **事务边界**：下单扣库存在单事务内完成，使用乐观锁 `version` 防止超卖。
