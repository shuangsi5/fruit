## 1. 测试目的与范围

### 1.1 测试目的

1. 验证系统核心业务规则与智能算法的正确性：订单状态机、统一响应与错误码、混合推荐评分、临期与损耗预警分级。
2. 验证工程可构建性：后端 Maven 编译与单元测试、前端生产构建。
3. 形成一套覆盖三端全部功能需求、异常边界与非功能诉求的可执行验收清单，为课程答辩与后续端到端联调提供依据。
4. 建立「需求编号 → 测试用例编号」的追踪关系，保证 FR/NFR/INT 条目可验证、可回溯。

### 1.2 测试范围

**范围内：**

- 认证与权限：注册、登录、Token 鉴权、角色隔离、水平越权防护、禁用账号。
- 用户端：分类浏览、搜索筛选、商品详情、购物车、下单支付、订单跟踪、售后申请、收货地址、个性化推荐、投诉提交。
- 商家端：商品上架/编辑/下架、库存调整、临期与预警处理、订单发货、售后审核、销售报表。
- 平台端：商家审核、用户管理、投诉处理、数据总览。
- 智能特性：推荐评分公式、协同过滤、冷启动热销兜底、临期阈值、损耗阈值、综合等级取 max。
- 非功能：性能、并发安全、密码存储、浏览器兼容与响应式。

**范围外（本次未覆盖）：**

- 真实支付网关、真实物流接口对接（项目明确为模拟实现，不在范围内）。
- 真实 MySQL 环境下的端到端 HTTP 联调（详见第 7 节限制说明）。
- 200 并发压测与长时间稳定性测试。
- 多浏览器、多分辨率的实机兼容性实测。

## 3. 测试策略与方法

### 3.1 测试策略

采用「**分层验证 + 设计态用例清单**」组合策略：

1. **底层逻辑单测（已执行）**：对不依赖数据库与外部中间件的纯逻辑组件做 JUnit 单元测试，快速验证算法与规则正确性。
2. **构建验证（已执行）**：后端 `mvn package`、前端 `npm run build`，保证交付物可编译、可产出。
3. **功能验收用例（设计态）**：按模块编写 51 条结构化用例，覆盖正常流、异常流与边界值，作为人工验收与端到端联调的执行清单。
4. **数据一致性核对（已执行）**：对种子数据的账号、密码存储形式、状态枚举与需求定义做静态比对。

### 3.2 测试方法

- **等价类划分与边界值分析**：重点用于临期天数（31/30/8/7/4/3/0）、损耗阈值（0.2/0.3/0.5/0.7/0.71）、库存等级（0/5/10/11）与售后时限（7 天边界）。
- **状态机路径覆盖**：合法流转（0→1→2→3→5）与非法流转（0→2、0→3、4→0、3→0、2→0）成对验证。
- **异常场景注入**：库存不足、支付超时、Token 失效、越权访问、参数缺失、重复提交、超时申诉。
- **需求追踪**：每条用例标注关联 FR/NFR/INT 编号，确保 32 FR、18 NFR、14 INT 中可测试条目均有对应用例。

### 3.3 不采用的测试方式与原因

- 未采用 Testcontainers/H2 做接口集成测试：当前阶段缺少真实 MySQL 实例，且团队分工中后端单测定位为「纯逻辑不依赖数据库」。
- 未采用 Playwright/Selenium 做 E2E：前端仅完成构建验证，未启动后端服务，无法形成闭环。
- 以上均在第 7 节作为遗留风险列出并给出改进建议。

## 7. 缺陷清单与处理情况

### 7.1 功能缺陷

已执行范围内的 18 个后端单元测试全部通过，前端构建成功，种子数据静态核对无误，**未发现功能性缺陷或失败用例**（失败数 0）。

### 7.2 发现的一致性问题（非代码功能缺陷）

| 编号 | 问题描述 | 影响 | 处理情况 |
|---|---|---|---|
| ISSUE-01 | 登录页一键填充账号与种子数据不一致（历史问题） | 曾导致点击快捷按钮登录失败 | 前端已修正：一键填充现使用真实种子账号，001 账号零残留，重新构建通过；文档侧保留真实账号说明作为双重保险 |

> 说明：该问题属于「页面演示文案与种子数据不一致」的配置类问题，不影响接口功能与鉴权逻辑，故不计入功能性缺陷数。

### 7.3 未构成缺陷的观察项

- 后端 README 标注 Java 17，实际验证 JVM 为 JDK 21。Spring Boot 3.2.5 兼容 JDK 21，构建与测试均通过，不视为缺陷。
- 种子数据中商家 id=3「待审果铺」的 `user_id=4` 指向 `user01`（USER 角色），导致该待审商家无独立 MERCHANT 登录账号。平台端「商家审核」仍可正常展示并审核该商家；如需以该商家身份登录，需额外注册 MERCHANT 账号，本次不作为缺陷处理。

## 8. 遗留风险与改进建议

### 8.1 遗留风险

| 编号 | 风险 | 影响程度 | 说明 |
|---|---|---|---|
| RISK-01 | 未连接真实 MySQL 做端到端联调 | 高 | 46 个接口的 HTTP 行为、事务边界、鉴权过滤器、MyBatis-Plus 映射均未实测；51 条功能用例处于设计态 |
| RISK-02 | 200 并发性能与无超卖未压测 | 高 | NFR-PERF-01~05 的 P95 与并发指标无法确认，乐观锁冲突处理仅靠代码审查 |
| RISK-03 | 多浏览器与多分辨率未实测 | 中 | NFR-COMP-01/02 的响应式与兼容性结论基于源码审查（media query 已实现），未实机验证 |
| RISK-04 | 登录页一键填充账号与种子数据不一致 | 低（已关闭） | 前端已修正并复核通过，详见 ISSUE-01 |
| RISK-05 | 定时任务与推荐缓存未运行时验证 | 中 | 每日 02:00 预警扫描、30 分钟推荐缓存仅完成配置核对，未观察运行时日志 |
| RISK-06 | 支付与物流为模拟实现 | 低 | 项目范围明确排除真实网关，属预期限制 |

### 8.2 改进建议

1. 部署真实 MySQL 8 实例并导入 `sql/init.sql`，按《测试用例》51 条清单执行端到端验收，重点覆盖下单支付、发货、售后、审核四条主链路。
2. 引入 Testcontainers 或内存数据库补充接口集成测试，将 46 个接口纳入 CI；在 CI 中固化 `mvn test` 与 `npm run build`。
3. 使用 JMeter 或 k6 对查询、推荐、下单接口做 200 并发压测，验证 P95 与无超卖。
4. 使用 Playwright 补充三端关键流程 E2E 测试，并覆盖 Chrome/Edge 与移动视口。
5. 统一登录页一键填充账号与种子数据（ISSUE-01），或在页面提示中直接展示真实账号。
6. 对每日 02:00 预警扫描与推荐缓存增加运行时日志与告警，验证 INT-WARN-08、INT-REC-06 的运行时行为。
7. 生产部署前务必修改 `application.yml` 中的数据库密码与 JWT 密钥，禁止使用默认演示凭据。

## 9. 测试结论

1. **已执行验证全部通过**：后端 4 个测试类、18 个 JUnit 单元测试 100% 通过，覆盖订单状态机、统一响应与 25 个错误码、混合推荐评分与冷启动兜底、临期与损耗预警阈值及综合取 max；前端 `npm run build` 成功产出 716 个模块，24 个页面与 46 个接口封装完整。
2. **功能用例设计完备**：共设计 51 条结构化用例（其中异常/边界 22 条），覆盖 32 条 FR、18 条 NFR 与 14 条 INT 的可测试条目，可作为人工验收与端到端联调的完整清单。
3. **执行范围内无失败**：失败用例数 0，未发现功能性缺陷；发现 1 项页面演示账号与种子数据不一致问题，前端已修正并复核通过，文档侧保留真实账号说明作为双重保险。
4. **限制须如实说明**：本次未连接真实 MySQL 做端到端联调，51 条功能用例中 44 条处于设计态，性能压测与多浏览器兼容未实测。相关风险已在第 8 节列明并给出改进建议。
5. **综合判定**：系统在当前阶段达到课程大作业「可编译、可构建、核心规则可验证、交付文档完整」的质量基线，同意进入 P6 交付文档与 P7 整合汇总阶段；建议在具备真实数据库环境后按《测试用例》完成端到端验收，以闭环 RISK-01 与 RISK-02。
