## 1. 文档说明

### 1.1 编写依据

本测试用例集依据以下已冻结基线编写，确保「需求 → 设计 → 测试」可双向追溯：

- `docs/01-需求分析/需求规格说明书.md`：32 条功能需求（FR）、18 条非功能需求（NFR）、14 条智能规则（INT）、订单/售后状态定义与 6.4 节术语映射。
- `docs/02-系统设计/API接口契约.md`：46 个接口、25 个错误码、统一响应结构与鉴权约定。
- `docs/02-系统设计/数据库设计.md`：17 张表与全部枚举码。
- `backend/src/test/java/com/fruittrade/` 下 4 个测试类共 18 个 JUnit 用例（实际已执行）。
- `frontend/src/views/**` 页面源码（按钮、菜单、提示文案以此为准）。
- `sql/init.sql` 实际种子数据（真实可用账号以此为唯一定论）。

### 1.2 用例状态说明

本用例集为**功能验收设计态**清单，可作为人工验收与后续端到端联调的执行依据。当前实际已执行的验证只有两类：

1. 后端 18 个纯逻辑 JUnit 单元测试（不依赖 MySQL），全部通过；
2. 前端 `npm run build` 构建验证，成功产出 716 个模块。

除已在「实际结果」中标注为「已通过（单测覆盖）」或「已核对」的条目外，其余用例均标注为「待执行（未连接真实 MySQL 做端到端联调）」。本用例集**不声称已完成端到端功能测试**，以避免伪造未执行的测试结果。
