## 1. 项目目标与范围

### 1.1 项目目标
面向本地果农与水果经销商，构建一套覆盖「货源上架 → 客户下单 → 库存管理 → 物流配送 → 售后服务」全链路的三端智能交易系统，并以 UML 模型与过程文档完整呈现软件工程开发流程。

### 1.2 功能范围
| 端 | 核心功能 |
|---|---|
| 用户端 | 浏览水果分类、商品详情、购物车、下单支付、订单状态跟踪（待发货/运输中/已完成）、售后申请（退款/退货）、个性化推荐 |
| 商家端 | 商品上下架、库存管理与不足预警、订单发货、售后处理、销售报表、临期/损耗预警 |
| 平台管理端 | 商家资质审核、用户账号管理、平台投诉处理、数据总览 |

### 1.3 智能特性
1. **基于历史购买记录的推荐**：采用协同过滤（User-Based CF）＋ 热销兜底混合策略，输出「猜你喜欢」。
2. **库存损耗与临期预警**：结合保质期（shelf_life_days）、生产日期、近期销量，计算临期阈值与损耗风险等级，主动推送商家。

### 1.4 不在范围内
- 真实支付网关对接（采用模拟支付状态流转）
- 第三方物流实时轨迹（采用模拟物流状态节点）
- 移动端原生 App（采用响应式 Web）

## 2. 技术栈与架构决策

| 层次 | 技术选型 | 说明 |
|---|---|---|
| 后端 | Spring Boot 3.x + Java 17 | 单体分层架构，RESTful API |
| 持久层 | MyBatis-Plus + MySQL 8.0 | SQL 脚本建模，便于课程追溯 |
| 安全 | Spring Security + JWT | 三端角色鉴权（USER/MERCHANT/ADMIN） |
| 前端 | Vue 3 + Vite + Vue Router + Pinia + Axios | 单工程多角色路由，响应式布局 |
| 图表 | ECharts | 销售报表可视化 |
| 建模 | PlantUML / Mermaid | 文本化 UML，随代码版本管理 |
| 构建 | Maven（后端）/ npm（前端） | 一键启动脚本 |

> 决策理由：团队对 Java 与 Vue 熟悉度最高；单体架构便于课程演示与本地部署；文本化 UML 保证模型与代码同库可追溯。

## 6. 进度跟踪机制
- 每个阶段由负责智能体写入对应目录并回报主管；
- 主管在任务看板更新状态，并将阶段结论写入「周报与周会纪要」；
- 每阶段结束时执行一次 Git 提交，形成可追溯的版本节点。

## 7. 风险管理
| 风险 | 应对 |
|---|---|
| 三端功能范围过大 | 采用 MVP 策略，核心链路优先，智能特性以规则算法实现 |
| 前后端接口不一致 | 由架构设计阶段先冻结 API 契约，后端按契约实现，前端按契约对接 |
| 文档与代码版本脱节 | 所有产物同仓库管理，报告章节注明版本与撰写成员 |
| 环境依赖导致无法运行 | 提供详细部署说明与 SQL 初始化脚本，附常见故障排查 |

## 8. 验收标准
1. 后端服务可启动，核心 API 可返回正确数据；
2. 前端三端页面可交互并完成一次完整下单流程；
3. 需求/设计/测试/部署文档齐全，UML 图不少于 8 类；
4. 大作业报告各章节均注明撰写成员，且与 Git 版本对应。
