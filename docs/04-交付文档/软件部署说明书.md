## 1. 部署架构

系统采用前后端分离、同机部署的轻量架构。三端前端共用一套 Vue 3 工程，构建为静态资源；后端为独立 Spring Boot 可执行 JAR；MySQL 8 作为业务主库。开发模式由 Vite 开发服务器提供 `/api` 代理，生产模式由 Nginx 统一托管静态资源并反向代理 `/api`，实现同域访问、规避跨域。

```
                    ┌──────────────┐
   用户 / 商家 / 管理员 → │  浏览器（三端） │
                    └──────┬───────┘
                           │ HTTP/HTTPS
                    ┌──────▼───────┐
                    │    Nginx     │  静态资源 + /api 反向代理
                    └───┬──────┬───┘
            静态资源    │      │  /api 反向代理
              ┌─────────┘      └────────┐
       ┌──────▼──────┐          ┌───────▼──────┐
       │ 前端静态目录 │          │ Spring Boot  │
       │  frontend/  │          │   :8080      │
       │    dist/    │          └───┬──────────┘
       └─────────────┘              │
                             ┌──────▼──────┐
                             │  MySQL 8    │
                             │fruit_trade_db
                             └─────────────┘
```

对应设计图：`docs/uml/部署图.puml` 与 `docs/uml/images/部署图.svg`。

## 3. 数据库初始化

### 3.1 启动 MySQL 并导入脚本

方式一：命令行导入（推荐）。在项目根目录执行：

```bash
mysql -u root -p < sql/init.sql
```

按提示输入 MySQL root 密码。`sql/init.sql` 会自动执行 `DROP DATABASE IF EXISTS fruit_trade_db` 与 `CREATE DATABASE`，因此**导入会覆盖同名数据库**，执行前请确认无需保留现有数据。

方式二：先建库再导入（适用于账号无 DROP 权限的场景）：

```bash
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS fruit_trade_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root -p fruit_trade_db < sql/init.sql
```

> 注意：`init.sql` 首行包含 `DROP DATABASE IF EXISTS fruit_trade_db;`，若账号无建库/删库权限，需要先移除该行再导入。

### 3.2 导入结果核对

导入成功后应包含 17 张表：`sys_user`、`merchant`、`category`、`product`、`product_image`、`inventory`、`cart`、`address`、`orders`、`order_item`、`payment_record`、`logistics`、`after_sale`、`complaint`、`audit_record`、`inventory_log`、`recommendation_log`。

核对命令：

```bash
mysql -u root -p -e "USE fruit_trade_db; SHOW TABLES; SELECT COUNT(*) FROM product; SELECT username, role FROM sys_user;"
```

预期：`product` 表 20 条记录，`sys_user` 表 6 条记录（admin、merchant01、merchant02、user01、user02、user03）。

### 3.3 种子数据账号

密码统一为 `123456`（BCrypt 加密存储）：

| 账号 | 角色 | 说明 |
|---|---|---|
| `admin` | ADMIN | 平台管理员 |
| `merchant01` | MERCHANT | 鲜果优选，已审核营业中 |
| `merchant02` | MERCHANT | 绿园鲜果，已审核营业中 |
| `user01` / `user02` / `user03` | USER | 普通用户 |

注意：登录页一键填充账号已修正为真实种子账号，可直接点击；若仍无法登录请手动输入上述账号。

## 5. 前端部署

### 5.1 开发模式启动

```bash
cd frontend
npm install
npm run dev
```

默认访问 `http://localhost:5173`。`vite.config.js` 已配置代理：

```js
proxy: {
  '/api': {
    target: 'http://localhost:8080',
    changeOrigin: true
  }
}
```

所有以 `/api` 开头的请求会转发到后端 8080 端口。Axios 的 `baseURL` 统一为 `/api`。**启动前端前请确保后端已在 8080 端口运行。**

### 5.2 生产构建

```bash
cd frontend
npm run build
```

构建产物输出到 `frontend/dist/`，包含 `index.html` 与带 hash 的静态资源文件。本地预览构建产物：

```bash
npm run preview
```

### 5.3 生产部署建议（Nginx）

1. 将 `frontend/dist/` 内容复制到 Nginx 静态目录（如 `/var/www/fruit-trade/dist`）。
2. 配置 `/api` 反向代理到后端，并启用 `try_files` 支持 Vue Router 的 History 模式。
3. 关键配置示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/fruit-trade/dist;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    gzip on;
    gzip_types text/css application/javascript application/json;
}
```

4. 后端 JAR 建议以 `systemd` 托管，实现开机自启与崩溃重启。示例 service 文件：

```ini
[Unit]
Description=Fruit Trade Backend
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/fruit-trade
ExecStart=/usr/bin/java -jar /opt/fruit-trade/fruit-trade-backend-1.0.0.jar
Restart=always

[Install]
WantedBy=multi-user.target
```

5. 启用 HTTPS、修改默认密码与 JWT 密钥、最小化开放端口、定期更新依赖补丁。

## 7. 常见故障排查

| 现象 | 可能原因 | 排查与处理 |
|---|---|---|
| 后端启动失败，提示端口占用 | 8080 端口已被其他进程占用 | 查找并结束占用进程；或修改 `application.yml` 的 `server.port` 并同步修改前端代理 `target` |
| 后端启动报数据库连接失败 | MySQL 未启动、URL/账号密码错误、驱动缺失 | 确认 MySQL 运行；核对 `spring.datasource.url`、`username`、`password`；确认已导入 `init.sql` |
| 接口返回 401 | Token 缺失或过期 | 检查请求头 `Authorization: Bearer <token>`；重新登录获取 Token；确认 `jwt.expiration` 未设置过短 |
| 接口返回 403 | 角色权限不足或商家未通过审核 | 确认账号角色与 `merchant.audit_status`；管理员先在「商家审核」中执行「通过」 |
| 前端页面空白 | 静态资源路径错误或构建失败 | 检查 Nginx `root` 与 `try_files` 配置；重新执行 `npm run build`；查看浏览器控制台报错 |
| 接口 404 或跨域错误 | 开发代理未生效或 Nginx 未配置 `/api` | 开发模式检查 `vite.config.js` 代理；生产模式检查 Nginx `location /api/`；确认后端 `cors.enabled` |
| 商品列表为空 | 无上架商品或逻辑删除条件过滤 | 确认 `product.status = 1`、`deleted = 0`；商家先上架商品 |
| 下单提示库存不足 | 库存为 0 或并发预占冲突 | 检查 `inventory.stock`；商家补货后重试；关注乐观锁冲突码 40902 |
| 中文乱码 | 字符集不一致 | 确认库表 utf8mb4、连接参数含 `characterEncoding=utf8`；重新导入 `init.sql` |
| 预警不更新 | 定时任务未执行 | 检查 `warning.scan-cron` 与任务日志；可临时调整为高频表达式验证后恢复 |
| npm 安装很慢或失败 | 默认 registry 网络慢、依赖缓存损坏 | 切换国内镜像源后重试；执行 `npm cache clean --force`；删除 `node_modules` 与 `package-lock.json` 后重新安装 |
| 登录页一键填充账号无法登录 | 页面填充值与种子数据不一致（前端已修正） | 手动输入真实账号，详见使用说明书 FAQ |
| 测试执行报无测试用例 | 测试类未被识别 | 确认测试类位于 `backend/src/test/java/com/fruittrade/`；确认 JUnit Jupiter 依赖由 Spring Boot Starter Test 提供 |

## 8. 卸载与回滚

### 8.1 卸载步骤

1. 停止后端进程：`Ctrl+C`（前台）或 `systemctl stop fruit-trade-backend`（systemd 托管）。
2. 停止 Nginx：`systemctl stop nginx`（如适用）。
3. 停止开发服务器：在 Vite 终端按 `Ctrl+C`。
4. 删除构建产物：`rm -rf frontend/dist`。
5. 删除依赖目录（可选）：`rm -rf frontend/node_modules`、`rm -rf backend/target`。
6. 删除数据库（**不可逆，执行前务必备份**）：`mysql -u root -p -e "DROP DATABASE fruit_trade_db;"`。

### 8.2 回滚步骤

1. 若修改了配置，先恢复 `application.yml`、`vite.config.js` 的备份版本。
2. 若数据库已被覆盖，使用升级前的 `mysqldump` 备份恢复：

```bash
mysql -u root -p fruit_trade_db < backup_YYYY-MM-DD.sql
```

3. 若需恢复至初始种子状态，重新导入 `sql/init.sql`（注意会清空现有业务数据）。
4. 使用旧版本 JAR 或前端构建产物替换当前版本，重启服务。
5. 按第 6 节验证清单重新核对。

> 建议在任何升级或数据变更操作前执行备份：`mysqldump -u root -p fruit_trade_db > backup_$(date +%F).sql`。

## 9. 运维建议

- 每日定时全量备份数据库并保留最近 30 天，升级或数据变更前后额外备份。
- 生产环境将 `logging.level.com.fruittrade` 从 `debug` 调整为 `info`，并配置日志轮转。
- 启用 Spring Boot Actuator `/actuator/health` 做健康检查（生产限制访问来源）。
- 监控数据库连接数、慢查询、磁盘空间及 ERROR 日志，异常时及时告警。
- 修改默认数据库密码与 JWT 密钥，禁止使用演示凭据。
