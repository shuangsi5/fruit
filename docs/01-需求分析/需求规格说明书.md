## 1. 引言

### 1.1 编写目的

本文档用于明确「水果交易智能管理系统」的完整需求边界，作为后续系统设计、编码实现、测试验收与课程答辩的共同依据。具体目标包括：

1. 界定三端（用户端、商家端、平台管理端）的功能范围与优先级，避免开发阶段需求蔓延；
2. 将业务语言转化为可验证的功能需求条目（FR 编号），每条均给出可度量的验收要点；
3. 明确智能特性（个性化推荐、临期与损耗预警）的可用规则与判定口径，使其可被工程实现而非停留在概念层；
4. 定义订单与售后两类核心业务状态，为状态机设计、接口契约与测试用例提供统一语义；
5. 建立需求追踪矩阵，保证「需求 → 用例 → 设计 → 测试」双向可追溯，满足课程工程化评分要求。

本文档面向读者：项目负责人、架构设计人员、前后端开发人员、测试人员及课程评审教师。

### 1.2 范围

本系统面向本地果农与水果经销商，覆盖「货源上架 → 客户下单 → 库存管理 → 物流配送 → 售后服务」全链路，提供三套角色视图：

- **用户端（Web 响应式）**：面向终端消费者，完成商品浏览、下单支付、订单跟踪、售后申请与个性化推荐查看。
- **商家端（Web 响应式）**：面向果农/经销商，完成商品上下架、库存管理、订单发货、售后处理、销售报表与临期损耗预警处理。
- **平台管理端（Web 响应式）**：面向平台运营人员，完成商家资质审核、用户账号管理、投诉处理与数据总览。

明确不在本次范围内的事项（依据项目计划 v1.0）：

| 排除项 | 说明 | 替代方案 |
|---|---|---|
| 真实支付网关对接 | 不接入微信/支付宝真实资金通道 | 模拟支付状态流转，记录支付流水号 |
| 第三方物流实时轨迹 | 不调用快递公司实时接口 | 由商家录入模拟物流节点（已发货/运输中/已签收） |
| 移动端原生 App | 不开发 Android/iOS 原生包 | 响应式 Web，适配主流桌面与移动浏览器 |
| 多语言与跨境结算 | 不做国际化 | 仅简体中文、人民币计价 |

### 1.4 术语表

| 术语 | 英文/代号 | 定义 |
|---|---|---|
| 三端 | Three-end | 用户端、商家端、平台管理端的合称，共用一套后端服务与角色鉴权 |
| SKU | Stock Keeping Unit | 最小库存单位，本系统中一个具体商品（如果农 A 的 500g 装阳光玫瑰） |
| 临期 | Near-expiry | 剩余保质期天数低于系统阈值的在售商品状态，需商家处理 |
| 损耗风险 | Loss Risk | 商品在保质期内未能售出而造成损失的可能性，由临期程度与销量趋势综合判定 |
| 安全库存 | Safety Stock | 为避免断货而设定的最低库存量，低于该值触发补货提示 |
| 预占库存 | Reserved Stock | 下单时临时锁定的库存，支付超时或失败后自动释放 |
| 协同过滤 | User-Based CF | 基于「购买过相似商品的用户也购买了什么」的推荐算法 |
| 热销兜底 | Hot-selling Fallback | 当协同过滤无足够数据时，用近期销量 Top-N 商品填充推荐位 |
| 售后单 | After-sale Order | 用户发起退款/退货申请后生成的服务单，独立于商品订单存在状态 |
| 平台介入 | Platform Intervention | 商家超时未处理或用户申诉时，由平台管理员强制裁决售后争议的机制 |
| FR | Functional Requirement | 功能性需求编号 |
| NFR | Non-Functional Requirement | 非功能性需求编号 |

## 2. 系统总体描述

### 2.1 业务背景

本地果农与小型水果经销商普遍面临三类痛点：

1. **销路分散**：依赖线下批发与社群接龙，缺少统一的线上货架与订单入口，客户复购难以沉淀；
2. **库存靠经验**：水果保质期短，商家凭经验判断进货量与促销时机，临期损耗与断货缺货问题并存；
3. **售后无标准**：退款、退货、物流异常缺少统一流程与状态跟踪，纠纷处理成本高。

本系统以「轻量化三端 + 规则型智能」为设计定位：不追求大型电商的复杂营销体系，而是把交易主链路做通，并用可解释、可配置的规则算法解决推荐与损耗两个最贴合水果品类的智能诉求。课程层面，本项目同时承担完整呈现需求、设计、编码、测试过程文档的教学目标。

### 2.2 干系人（Stakeholders）

| 干系人 | 角色标识 | 主要诉求 | 在本系统中的权限边界 |
|---|---|---|---|
| 终端消费者 | USER | 买到新鲜水果、下单便捷、售后有保障 | 仅浏览商品、管理本人购物车/订单/售后/地址 |
| 果农/经销商 | MERCHANT | 快速上架货源、减少损耗、看清销售情况 | 管理本店商品/库存/订单/售后，查看本店报表 |
| 平台运营人员 | ADMIN | 平台秩序、商家资质合规、投诉可处理 | 审核资质与商品、管理账号、介入争议、查看全站数据 |
| 课程指导教师 | 评审方 | 文档齐全、过程可追溯、系统可演示 | 只读验收，不参与运行时操作 |
| 开发团队 | 实现方 | 需求明确、边界清晰、可测试 | 按 FR/NFR 实现，维护需求追踪矩阵 |

### 2.3 运行环境约束

| 约束类别 | 具体要求 |
|---|---|
| 后端运行环境 | JDK 17 及以上；Spring Boot 3.x；Maven 3.8+ 构建 |
| 数据库 | MySQL 8.0，字符集 utf8mb4，事务隔离级别 READ COMMITTED 或以上 |
| 前端运行环境 | Node.js 18+；Vue 3 + Vite；现代浏览器（Chrome/Edge 最近两个大版本） |
| 部署形态 | 本机单机部署，前后端分离但同机运行；采用模拟支付与模拟物流 |
| 网络假设 | 局域网或本机回环访问，无公网支付回调需求 |
| 浏览器能力 | 不依赖浏览器插件；需启用 JavaScript 与本地存储（用于购物车临时态） |
| 数据规模假设 | 商品 SKU ≤ 5000，注册用户 ≤ 10000，日订单量 ≤ 2000（课程演示量级） |

### 2.4 假设与依赖

1. **假设 A1**：商家入驻时提交的营业执照/身份信息为真实信息，平台审核以人工核验为主，系统仅留存图片与审核结论，不做联网验真。
2. **假设 A2**：所有商品均维护「生产日期」与「保质期天数」字段；若商家缺失填写，系统按默认 7 天处理并在商品详情标注提示。
3. **假设 A3**：用户收货地址与联系方式由用户自行维护，系统不对真实地址做物流地址校验。
4. **假设 A4**：支付为模拟流程，成功/失败由用户在模拟支付页选择触发，用于完整演示状态流转；不产生真实资金流。
5. **假设 A5**：物流信息由商家手工录入节点，不对接第三方接口；用户端展示的是节点时间线而非实时地图轨迹。
6. **依赖 D1**：后端需提供统一的角色鉴权能力（USER/MERCHANT/ADMIN 三角色隔离），否则越权控制类需求无法验收。
7. **依赖 D2**：架构设计阶段需先冻结核心实体（用户、商家、商品、订单、订单明细、售后单、预警记录）的数据契约，推荐与预警算法方可读取所需字段。
8. **依赖 D3**：系统参数（临期阈值、预警分级参数、支付超时时长、售后处理时效）需支持配置化，便于演示不同规则效果。

## 3. 功能性需求

> 优先级定义：**P0（最高，核心链路，缺一不可）**；**P1（高，重要业务，首版必须交付）**；**P2（中，增强体验，可迭代）**；**P3（低，锦上添花）**。
> 每条需求的「验收要点」均可直接转化为测试用例，供测试阶段使用。

### 3.1 用户端功能需求

| 编号 | 功能名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-USR-01 | 注册与登录 | 用户以手机号注册并设置密码，登录成功后签发令牌；支持退出登录与会话过期提示。 | P1 | ① 手机号格式校验（11 位）；② 重复手机号注册被拒绝并给出明确提示；③ 密码以不可逆方式存储；④ 未登录访问购物车/订单接口返回 401 并跳转登录页。 |
| FR-USR-02 | 浏览水果分类 | 首页展示水果分类导航（如浆果类、柑橘类、热带水果、仁果类），点击分类进入商品列表。 | P1 | ① 分类列表与后台维护一致；② 空分类展示「暂无商品」占位；③ 分类切换后列表内容与分类匹配。 |
| FR-USR-03 | 搜索与筛选商品 | 支持按商品名关键字搜索，并按价格区间、分类、是否有货、销量排序进行筛选。 | P2 | ① 关键字模糊匹配命中商品名；② 多条件组合筛选为「与」关系；③ 无结果时展示空状态与清空筛选入口。 |
| FR-USR-04 | 查看商品详情 | 展示商品图、名称、产地、单价、规格、库存、生产日期、保质期剩余天数、描述与累计销量。 | P1 | ① 字段与商家发布信息一致；② 库存为 0 时「加入购物车」按钮禁用并提示「已售罄」；③ 临期商品在详情页展示明确标识。 |
| FR-USR-05 | 管理购物车 | 支持加入商品、修改数量、删除条目、勾选结算；购物车按商家分组展示。 | P1 | ① 数量变更实时重算小计与合计；② 修改数量超过可售库存时自动修正为库存上限并提示；③ 关闭浏览器后购物车内容保留（本地存储或服务端持久化）；④ 空购物车不可进入结算。 |
| FR-USR-06 | 下单与支付 | 从购物车勾选商品生成订单，校验并预占库存，跳转模拟支付；支付成功生成订单并进入待发货，失败/超时释放库存。 | P0 | ① 提交订单时库存充足方可生成；② 订单金额 = Σ(单价×数量)，与购物车一致；③ 支付成功后订单状态为「待发货」，商家端可见；④ 支付失败或 30 分钟超时后库存回滚且订单为「已取消」；⑤ 全程无超卖（并发扣减正确性）。 |
| FR-USR-07 | 跟踪订单状态 | 在「我的订单」列表与详情查看状态（待支付/待发货/运输中/已完成/已取消/售后中）及物流节点时间线。 | P1 | ① 状态与商家/平台操作同步；② 时间线按时间倒序展示；③ 支持按状态标签筛选订单；④ 待支付订单展示「去支付」与「取消订单」入口。 |
| FR-USR-08 | 申请售后 | 对已发货/已完成订单发起退款或退货申请，填写原因并上传凭证图片。 | P1 | ① 仅允许售后时效内（签收后 7 天内）的订单发起；② 同一订单同一商品不可重复发起未完结售后；③ 提交后生成售后单，状态为「待审核」；④ 上传图片限制格式与大小并给出校验提示。 |
| FR-USR-09 | 查看个性化推荐 | 在首页与商品详情页展示「猜你喜欢」推荐位，可查看推荐理由标签。 | P2 | ① 有历史购买记录时推荐结果与算法输出一致且不含已下架商品；② 新用户展示热销兜底商品；③ 推荐位商品点击可进入详情；④ 推荐接口响应满足第 4.1 节性能要求。 |
| FR-USR-10 | 管理收货地址 | 支持地址的新增、编辑、删除、设为默认，下单时可选择地址。 | P2 | ① 默认地址唯一；② 删除默认地址后自动将剩余地址之一设为默认；③ 地址字段必填校验（收货人、手机号、详细地址）。 |
| FR-USR-11 | 商品评价 | 对已完成订单中的商品评分（1 至 5 星）并填写文字评价。 | P2 | ① 仅已完成订单可评价；② 每个订单商品仅可评价一次；③ 评价提交后商品详情展示平均评分。 |
| FR-USR-12 | 消息通知 | 在个人中心查看订单状态变更、售后结果、预警相关的系统通知。 | P3 | ① 关键节点自动生成通知；② 未读数量正确展示；③ 支持标记为已读。 |

### 3.2 商家端功能需求

| 编号 | 功能名称 | 需求描述 | 优先级 | 验收要点 |
|---|---|---|---|---|
| FR-MER-01 | 提交入驻资质 | 商家填写店名、联系人、联系方式，上传营业执照或身份证明，提交平台审核。 | P1 | ① 必填项与图片格式校验；② 提交后商家账号状态为「待审核」，无法上架商品；③ 可查看审核状态与驳回原因。 |
| FR-MER-02 | 商品上架 | 填写商品名称、分类、规格、单价、库存、生产日期、保质期天数、图片与描述，发布到前台。 | P0 | ① 必填项完整性与数值范围校验（价格>0、库存≥0、保质期>0）；② 上架后用户端分类列表可见；③ 生产日期不得晚于当前日期；④ 图片上传失败可重试且不产生脏数据。 |
| FR-MER-03 | 商品编辑与下架 | 修改在售商品信息，或执行下架使其不再对用户展示。 | P1 | ① 编辑已有订单关联商品时，历史订单商品快照不变；② 下架后前台不可搜索/不可购买；③ 可重新上架。 |
| FR-MER-04 | 库存管理与不足预警 | 查看库存台账，设置安全库存；当可售库存低于阈值时收到补货提示。 | P1 | ① 库存变动（上架/下单/取消/盘点）均留痕；② 低于安全库存时触发提示且列表标色；③ 库存不允许为负数。 |
| FR-MER-05 | 订单处理与发货 | 查看待发货订单，拣货确认后录入物流公司/运单号并点击发货。 | P0 | ① 仅「待发货」订单可发货；② 发货后订单状态变为「运输中」，用户端同步可见；③ 运单号非空校验；④ 发货操作产生一条物流节点记录。 |
| FR-MER-06 | 售后处理 | 查看售后申请，执行同意/拒绝并填写处理意见；同意后触发退款/退货流程。 | P1 | ① 仅「待审核」售后单可处理；② 处理意见为必填；③ 同意后售后单为「已同意」并通知用户；④ 拒绝后用户可申诉进入平台介入。 |
| FR-MER-07 | 查看销售报表 | 按日/周/月查看销售额、订单量、客单价、销量 Top 商品，支持图表展示。 | P2 | ① 时间范围切换数据正确；② 汇总值与订单明细一致（金额保留两位小数）；③ Top 商品排序正确；④ 空数据区间展示友好提示。 |
| FR-MER-08 | 临期与损耗预警 | 系统按规则计算临期与损耗风险并分级推送；商家可查看预警列表并执行促销/下架/忽略处理。 | P0 | ① 预警按红/橙/黄三级准确分级；② 每条预警附计算依据（剩余天数、销量变化率、可售天数）；③ 处理动作写入预警记录可追溯；④ 忽略操作需选择原因。 |

## 6. 业务规则与状态定义

### 6.1 订单状态定义与流转

| 状态 | 代号 | 含义 | 允许的前驱 | 允许的后继 |
|---|---|---|---|---|
| 待支付 | PENDING_PAYMENT | 订单已创建，库存已预占，等待支付 | — | 待发货、已取消 |
| 待发货 | PENDING_SHIPMENT | 支付成功，等待商家拣货发出 | 待支付 | 运输中、已取消、售后中 |
| 运输中 | SHIPPING | 商家已发货，物流节点推进中 | 待发货 | 已完成、售后中 |
| 已完成 | COMPLETED | 用户确认收货或物流签收，交易完成 | 运输中、售后中 | 售后中 |
| 已取消 | CANCELLED | 订单终止，库存已释放，未发生资金结算 | 待支付、待发货、售后中 | — |
| 售后中 | AFTER_SALE | 存在未完结的售后单 | 待发货、运输中、已完成 | 已完成、已取消 |

**订单业务规则：**

- **OR-01**：订单金额在生成时由商品快照价格计算，后续商品调价不影响历史订单金额。
- **OR-02**：支付倒计时 30 分钟（FR-ADM-07 可配置），超时未支付自动转为「已取消」并释放预占库存。
- **OR-03**：「待支付」与「待发货」状态允许用户取消；「运输中」「已完成」不可直接取消，只能走售后流程。
- **OR-04**：库存预占采用「下单锁定 + 支付确认扣减」两段式，取消/超时/失败均释放，禁止超卖。
- **OR-05**：用户确认收货后订单转为「已完成」；若售后单完结且整单退款并退货，订单最终状态置为「已取消」并标记退款完成；部分退款则回到「已完成」并标记已退款金额。
- **OR-06**：订单状态变更须生成通知与状态变更记录，供用户端时间线与平台日志使用。

### 6.2 售后状态定义与流转

| 状态 | 代号 | 含义 | 允许的后继 |
|---|---|---|---|
| 待审核 | PENDING_REVIEW | 用户已提交，等待商家处理 | 已同意、已拒绝 |
| 已同意 | APPROVED | 商家同意，进入退款/退货执行 | 已完成 |
| 已拒绝 | REJECTED | 商家拒绝，附处理意见 | 已完成（用户接受）、待审核（平台裁决后重开） |
| 已完成 | COMPLETED | 退款/退货执行完毕并闭环 | — |

**售后业务规则：**

- **AR-01**：可申请时效为签收后 7 天内；超时不可发起（FR-USR-08 验收要点）。
- **AR-02**：售后类型分为「仅退款」（未发货场景）与「退款退货」（已收货场景），商家处理时须匹配类型执行。
- **AR-03**：商家处理时效 48 小时（FR-ADM-07 可配置）；超时未处理，售后单自动进入平台待介入队列。
- **AR-04**：用户不服商家拒绝结论可发起申诉，售后单流转至平台介入，由管理员强制裁决；裁决结果对用户与商家均生效。
- **AR-05**：退款金额为商品实付金额（不含运费，运费规则简化不计）；部分退货按退货商品明细计算。
- **AR-06**：售后单完结后回写订单状态（按 OR-05），并记录完整的操作人、时间与意见。

### 6.3 关键计算口径汇总

| 计算项 | 公式 |
|---|---|
| 订单总价 | Σ(商品单价 × 购买数量)，保留两位小数 |
| 剩余保质期天数 | 生产日期 + 保质期天数 − 当前日期 |
| 临期判定 | 剩余天数 ≤ 3 或 剩余天数 / 保质期天数 ≤ 30% |
| 近 7 日日均销量 | 近 7 日销售件数 / 7 |
| 销量变化率 | (近 7 日日均 − 近 30 日日均) / 近 30 日日均 |
| 预计可售天数 | 当前库存 / max(近 7 日日均销量, 1) |
| 推荐权重（CF） | 邻居相似度 × 用户交互权重 + 频次归一化 × 0.3 |

### 6.4 P1 需求口径与 P2 设计枚举的术语映射

| P1 需求口径（本文档） | P2 设计枚举（系统设计文档） | 说明 |
|---|---|---|
| 待审核 | 待审核 | 完全一致 |
| 已同意 | 审核通过 / 处理中 | P2 将「同意后进入退款退货执行」拆为审核通过、处理中两态，合并对应 P1 的「已同意」 |
| 已拒绝 | 已驳回 | 同一语义不同措辞 |
| 已完成 | 已完成 | 完全一致 |

| P1 预警等级（本文档） | P2 设计枚举（系统设计文档） | 说明 |

| 绿色（正常） | 正常 | 不满足任何风险条件 |
| 黄色（低风险） | 注意 | 低于安全库存或临界临期 |

| 红色（高风险） | 严重 | 临期且无法在保质期内消化 |

| P1 商家资质审核口径 | P2 设计枚举（系统设计文档） | 说明 |
|---|---|---|
| 待审核 | 待审核 | 完全一致 |
