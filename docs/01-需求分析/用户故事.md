# 水果交易智能管理系统 — 用户故事

| 文档项 | 内容 |
|---|---|
| 文档名称 | 用户故事集 |
| 适用阶段 | P1 需求分析与功能建模 |
| 故事总数 | 20 条（用户端 7、商家端 7、平台管理端 6） |
| 估算方法 | 斐波那契数列 Story Point（1/2/3/5/8） |

> 格式约定：每条故事包含编号、角色、故事描述、验收标准（Given/When/Then）、优先级、预估 Story Point。
> 优先级与需求规格说明书一致：P0 最高、P1 高、P2 中、P3 低。

---

## 一、用户端故事

### US-USR-01 注册账号并登录

- **角色**：终端消费者（USER）
- **故事描述**：作为新用户，我希望用手机号注册并登录系统，以便保存购物车、查看订单并享受个性化推荐。
- **验收标准**：
  - Given 我在登录页且尚未注册，When 我输入合法的 11 位手机号、密码与确认密码并提交，Then 系统创建账号、提示注册成功并自动跳转到首页。
  - Given 我已注册，When 我输入正确手机号与密码并提交，Then 系统签发令牌并保持登录状态；输入错误密码时提示「手机号或密码错误」且不泄露账号是否存在。
  - Given 我处于未登录状态，When 我访问购物车或我的订单，Then 系统跳转登录页并在登录后回到原目标页。
- **优先级**：P1
- **预估 Story Point**：3

### US-USR-02 按分类浏览水果

- **角色**：终端消费者（USER）
- **故事描述**：作为想买水果的用户，我希望按分类浏览在售商品，以便快速定位感兴趣的水果品类。
- **验收标准**：
  - Given 我进入首页，When 页面加载完成，Then 展示全部水果分类导航且数量与后台维护一致。
  - Given 我在分类导航中点击「浆果类」，When 列表刷新，Then 仅展示该分类下已上架且有货的商品。
  - Given 某分类下暂无上架商品，When 我进入该分类，Then 展示「暂无商品，去看看其他分类」的空状态。
- **优先级**：P1
- **预估 Story Point**：2

### US-USR-03 搜索与筛选商品

- **角色**：终端消费者（USER）
- **故事描述**：作为有明确购买目标的用户，我希望按名称搜索并组合筛选商品，以便更快找到心仪商品。
- **验收标准**：
  - Given 商品列表页，When 我输入「阳光玫瑰」并搜索，Then 列表展示名称包含该关键字的在售商品。
  - Given 我已选择分类与价格区间，When 我按销量降序排序，Then 结果同时满足筛选条件并按销量从高到低排列。
  - Given 筛选条件无匹配结果，When 结果页渲染，Then 展示空状态与「清空筛选」按钮，点击后恢复全部商品。
- **优先级**：P2
- **预估 Story Point**：3

### US-USR-04 查看商品详情并加入购物车

- **角色**：终端消费者（USER）
- **故事描述**：作为准备购买的用户，我希望查看商品详情并加入购物车，以便核对产地、新鲜度与价格后再结算。
- **验收标准**：
  - Given 我在商品列表点击某商品，When 详情页加载，Then 展示图片、名称、产地、规格、单价、库存、生产日期、剩余保质期天数、销量与描述。
  - Given 该商品库存为 0，When 详情页渲染，Then 「加入购物车」按钮禁用并显示「已售罄」。
  - Given 商品处于临期状态，When 详情页渲染，Then 展示醒目的临期标识与剩余天数提示。
  - Given 我选择数量 2 并点击加入购物车，When 操作完成，Then 购物车中该商品数量增加 2 且页面给出成功提示。
- **优先级**：P1
- **预估 Story Point**：3

### US-USR-05 结算下单并完成模拟支付

- **角色**：终端消费者（USER）
- **故事描述**：作为选购完成的用户，我希望结算购物车并完成支付，以便商家收到订单并安排发货。
- **验收标准**：
  - Given 购物车中勾选了 2 件商品，When 我点击结算并提交订单，Then 系统生成订单且订单金额等于所选商品小计之和。
  - Given 提交订单时某商品库存不足，When 提交动作触发，Then 系统拒绝下单、提示库存不足的具体商品与可选替代数量，且不生成订单。
  - Given 订单处于待支付状态，When 我在模拟支付页选择支付成功，Then 订单状态变为「待发货」，库存预占转为实际扣减，商家端可见该订单。
  - Given 订单处于待支付状态，When 我选择支付失败或超过 30 分钟未支付，Then 订单变为「已取消」且预占库存被释放。
- **优先级**：P0
- **预估 Story Point**：8

### US-USR-06 跟踪订单状态与物流节点

- **角色**：终端消费者（USER）
- **故事描述**：作为已下单的用户，我希望随时查看订单状态与物流进度，以便掌握收货时间预期。
- **验收标准**：
  - Given 我进入「我的订单」，When 页面加载，Then 订单按状态标签分组展示，且每条订单显示当前状态中文标签。
  - Given 某订单已由商家发货，When 我查看订单详情，Then 展示运单号与按时间倒序排列的物流节点时间线。
  - Given 订单状态为「待支付」，When 我查看详情，Then 页面提供「去支付」与「取消订单」入口；状态为「运输中」时两者均不出现。
- **优先级**：P1
- **预估 Story Point**：3

### US-USR-07 申请售后并查看个性化推荐

- **角色**：终端消费者（USER）
- **故事描述**：作为收到有问题商品的用户，我希望在时效内申请退款或退货并跟踪处理进度；同时希望首页推荐符合我的口味。
- **验收标准**：
  - Given 某订单签收未满 7 天且存在售后资格，When 我提交售后申请（类型、原因、凭证图片），Then 生成状态为「待审核」的售后单并给出成功提示。
  - Given 同一商品的未完结售后单已存在，When 我再次提交，Then 系统拒绝并提示「已有处理中的售后申请」。
  - Given 我有历史购买记录，When 我访问首页推荐位，Then 展示 8 至 12 条推荐商品且不包含已下架、售罄及已购商品，并附推荐理由标签。
  - Given 我是无任何购买记录的新用户，When 我访问推荐位，Then 展示近 30 天热销商品作为兜底。
- **优先级**：P1
- **预估 Story Point**：5

## 二、商家端故事

### US-MER-01 提交入驻资质并等待审核

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为希望入驻平台的商家，我希望在线提交资质材料并查看审核进度，以便合法开展销售。
- **验收标准**：
  - Given 我填写店名、联系人、手机号并上传营业执照图片，When 我提交入驻申请，Then 系统保存资料并将商家状态置为「待审核」，提示预计审核时效。
  - Given 我缺少必传资质图片，When 我点击提交，Then 系统阻止提交并定位到缺失字段。
  - Given 平台已驳回我的申请，When 我登录后查看，Then 看到驳回原因并可修改后重新提交。
  - Given 我的商家状态为「待审核」或「已驳回」，When 我尝试上架商品，Then 操作被拒绝并提示需先通过资质审核。
- **优先级**：P1
- **预估 Story Point**：3

### US-MER-02 上架商品并维护库存与保质期信息

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为商家，我希望发布商品并完整填写库存与保质期信息，以便用户可购买且系统能正确计算临期风险。
- **验收标准**：
  - Given 我已通过资质审核，When 我填写商品名称、分类、规格、单价、库存、生产日期、保质期天数、图片与描述并提交，Then 商品上架成功并在用户端对应分类可见。
  - Given 我填写的生产日期晚于今天或价格小于等于 0，When 我提交，Then 系统拒绝并给出字段级错误提示。
  - Given 我上架的商品库存为 5、近 7 日日均销量为 2，When 我查看库存台账，Then 显示可售约 3 天且低于安全库存时给出补货提示。
  - Given 我需要更新价格或库存，When 我编辑商品并保存，Then 变更生效且历史订单中的商品快照价格保持不变。
- **优先级**：P0
- **预估 Story Point**：5

### US-MER-03 处理订单并发货

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为商家，我希望集中处理待发货订单并录入物流信息，以便用户及时收到商品。
- **验收标准**：
  - Given 存在状态为「待发货」的订单，When 我进入订单管理页，Then 按时间倒序列出这些订单并支持查看收货信息。
  - Given 我选择一笔待发货订单，When 我填写物流公司与非空运单号并点击发货，Then 订单状态变为「运输中」，用户端时间线新增发货节点。
  - Given 我尝试对「已取消」或「运输中」的订单执行发货，When 操作触发，Then 系统拒绝并提示当前状态不允许发货。
  - Given 我发货后，When 我查看该订单，Then 显示运单号、发货时间与物流节点记录。
- **优先级**：P0
- **预估 Story Point**：5

### US-MER-04 处理临期与损耗预警

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为商家，我希望系统提前告知哪些水果临期或滞销，以便通过促销或下架减少损耗。
- **验收标准**：
  - Given 某商品剩余保质期 2 天且库存高于近 7 日预计销量，When 预警任务执行，Then 生成红色预警并推送至我的消息中心，附剩余天数与可售天数等计算依据。
  - Given 某商品近 7 日日均销量比近 30 日下降 40%，When 预警任务执行，Then 生成橙色预警并标注「销量下滑」。
  - Given 我查看预警列表，When 我对红色预警选择「促销」并填写折扣，Then 预警状态闭环、生成处理记录，商品在前台展示促销信息。
  - Given 我选择「忽略」，When 我未填写原因，Then 系统阻止提交；填写原因后忽略生效且记录可追溯。
- **优先级**：P0
- **预估 Story Point**：5

### US-MER-05 审核并处理售后申请

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为商家，我希望集中处理用户售后申请并填写处理意见，以便规范地解决退款退货争议。
- **验收标准**：
  - Given 存在状态为「待审核」的售后单，When 我进入售后管理页，Then 展示申请类型、原因、凭证图片与关联订单信息。
  - Given 我同意退款退货申请，When 我填写处理意见并确认，Then 售后单变为「已同意」，触发退款流程并通知用户。
  - Given 我拒绝申请但未填写处理意见，When 我提交，Then 系统拒绝操作并提示必填原因。
  - Given 售后单不是「待审核」状态，When 我尝试再次处理，Then 系统拒绝并提示当前状态不可操作。
- **优先级**：P1
- **预估 Story Point**：3

### US-MER-06 查看销售报表

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为商家，我希望按时间查看销售额、订单量与热销商品，以便判断经营状况与进货策略。
- **验收标准**：
  - Given 我选择「本月」时间范围，When 报表加载，Then 展示销售额、订单量、客单价、销量 Top 10 商品，图表与数值一致。
  - Given 所选区间无订单数据，When 报表加载，Then 展示空状态提示而非报错。
  - Given 报表金额合计为 1234.56，When 我核对订单明细，Then 明细汇总金额与报表一致（保留两位小数）。
- **优先级**：P2
- **预估 Story Point**：5

### US-MER-07 库存盘点与平台通知处理

- **角色**：果农或水果经销商（MERCHANT）
- **故事描述**：作为商家，我希望定期盘点库存并处理平台通知，以便账实相符并及时响应平台要求。
- **验收标准**：
  - Given 某商品账面库存 20、实盘 18，When 我提交盘点，Then 系统生成盘亏 2 的调整记录且库存更新为 18。
  - Given 存在未结算的预占库存，When 我执行盘点，Then 预占部分不被覆盖，调整只针对可用库存。
  - Given 平台驳回了我的资质或要求补充材料，When 我打开消息中心，Then 看到对应通知、原因与响应入口。
- **优先级**：P2
- **预估 Story Point**：3

## 三、平台管理端故事

### US-ADM-01 审核商家入驻资质

- **角色**：平台管理员（ADMIN）
- **故事描述**：作为平台运营人员，我希望集中审核商家资质并留下审核痕迹，以便把好商家准入关。
- **验收标准**：
  - Given 存在「待审核」商家，When 我打开审核列表，Then 展示店名、联系人、资质图片与提交时间。
  - Given 我点击「通过」，When 确认提交，Then 商家状态变为「已通过」并获得上架商品权限，审核记录包含操作人与时间。
  - Given 我点击「驳回」但未填写原因，When 我提交，Then 系统阻止操作；填写后驳回生效且商家端可见原因。
- **优先级**：P1
- **预估 Story Point**：3

### US-ADM-02 管理用户账号

- **角色**：平台管理员（ADMIN）
- **故事描述**：作为平台运营人员，我希望查询并管理用户账号状态，以便处理违规账号与账号咨询。
- **验收标准**：
  - Given 我输入手机号片段查询，When 结果返回，Then 展示匹配用户列表及其订单数量与账号状态。
  - Given 某违规用户账号处于启用状态，When 我执行「禁用」，Then 该用户无法登录、既有令牌失效，操作被记录。
  - Given 重新启用被禁用账号，When 操作完成，Then 用户可正常登录且历史数据完整保留。
- **优先级**：P1
- **预估 Story Point**：3

### US-ADM-03 处理投诉并对售后争议进行平台介入

- **角色**：平台管理员（ADMIN）
- **故事描述**：作为平台客服，我希望处理用户投诉并裁决商家未及时处理的售后争议，以便保障用户权益与平台公信力。
- **验收标准**：
  - Given 某售后单商家超过 48 小时未处理，When 我打开平台介入列表，Then 该售后单自动出现在待介入队列并标注超时时长。
  - Given 用户发起申诉，When 我查看该售后单，Then 能看到商家处理意见与用户申诉理由。
  - Given 我作出「强制同意退款」裁决并填写理由，When 提交，Then 售后单按裁决执行、状态变更同步用户与商家，且裁决全程留痕。
  - Given 用户提交了投诉工单，When 我标记为「已处理」并填写结论，Then 投诉状态更新且用户端可见处理结论。
- **优先级**：P0
- **预估 Story Point**：5

### US-ADM-04 查看平台数据总览

- **角色**：平台管理员（ADMIN）
- **故事描述**：作为平台管理者，我希望在首页查看核心经营指标与预警概览，以便掌握平台运行状况。
- **验收标准**：
  - Given 我登录平台端，When 首页加载，Then 展示 GMV、订单量、活跃用户数、在售商品数、入驻商家数与预警数量。
  - Given 我选择时间范围「近 7 天」，When 指标刷新，Then 各指标与底层订单/用户/商品数据一致。
  - Given 我点击「预警数量」，When 页面跳转，Then 进入预警下钻列表，数量与总览一致。
- **优先级**：P1
- **预估 Story Point**：3

### US-ADM-05 配置系统参数与权限

- **角色**：平台管理员（ADMIN）
- **故事描述**：作为平台管理员，我希望配置临期阈值、支付超时时长等参数并管理后台角色权限，以便系统规则可灵活调整且操作可控。
- **验收标准**：
  - Given 我修改临期阈值为 5 天，When 保存成功，Then 下次预警任务按新阈值计算，且记录修改前后值与操作人。
  - Given 我输入非法阈值（负数或非数字），When 保存，Then 系统拒绝并提示合法范围。
  - Given 我为某管理员分配「仅客服」角色，When 该管理员登录，Then 仅看到客服相关菜单，访问运营菜单被拒绝。
- **优先级**：P2
- **预估 Story Point**：5

### US-ADM-06 审核商品与查询操作日志

- **角色**：平台管理员（ADMIN）
- **故事描述**：作为平台运营人员，我希望抽检违规商品并查询关键操作日志，以便维护平台秩序与事后追溯。
- **验收标准**：
  - Given 某商品被举报违规，When 我执行强制下架并填写原因，Then 该商品立即在用户端不可见，商家收到下架通知。
  - Given 我按操作人、时间与模块查询日志，When 条件匹配，Then 返回审核、禁用、强制下架、参数修改、平台裁决等记录。
  - Given 我尝试编辑或删除日志记录，When 操作触发，Then 系统不允许该操作，日志保持只读。
